## 3. 架构设计与技术栈审查 (Architecture Review)

### 3.1 技术栈选型合理性
- **选型结论**：`Python (FastAPI) + Vue 3 (Element Plus) + SQLite3 + Docker`
- **审查评价**：
  1. **开发效率与性能兼顾**：FastAPI 基于 Starlette 与 Pydantic，拥有原生异步支持及自动化交互式 API 调试文档（Swagger/OpenAPI），极度契合敏捷开发与实训答辩演示。
  2. **轻量与易维护性**：SQLite 采用单文件存储结合 WAL 并发模式，省去庞大的 MySQL 内存开销，极度适合高校服务器与轻量云主机一键启动；配合标准 SQLAlchemy 2.0 ORM，后续可平滑无缝升级迁移至 MySQL/PostgreSQL。
  3. **标准前后端分离**：采用 Vue 3 组合式 API + Vite 5 构建，配合 Nginx 反向代理，架构清晰，易于团队协同。

### 3.2 模块解耦与扩展性
- 控制层（API Routes）、服务层（Services）、数据模型层（Models）、数据传输层（Schemas）分层清晰，业务代码无 SQL 硬编码，可测性高。

## 4. 数据库设计审查 (Database Review)

1. **范式与一致性**：
   - 整体满足第三范式 (3NF)。
   - 在图书信息表中冗余保存 `available_copies` 字段，并在服务层通过原子事务保障与 `total_copies - borrowed_count` 强一致，大幅减少实时关联聚合查询开销。
2. **索引与查询优化**：
   - 对高频检索列 `isbn`、`title`、`author`、`card_number`、`record_no`、`due_date` 建立 B-Tree 索引，杜绝全表扫描。
3. **并发安全与事务防超卖**：
   - 在借阅操作时，使用带前置条件检查的更新语句：
     `UPDATE books SET available_copies = available_copies - 1 WHERE id = :id AND available_copies > 0;`
   - 利用关系型数据库的单行排他写锁，彻底杜绝并发超借问题。

## 5. API 规范与接口安全性审查 (API & Security Review)

1. **接口规范**：
   - 完全遵循 RESTful 规范，状态码、错误码统一规范，出入参由 Pydantic 强类型严格过滤。
2. **鉴权安全**：
   - 密码严禁明文入库，全部采用带动态盐的 `bcrypt` 哈希算法；
   - 采用标准 JWT Bearer Token 机制，Token 内包含唯一标识与角色，防止越权（横向越权与纵向越权已在依赖项 `get_current_active_user` 与 `RoleChecker` 中完全拦截）。
3. **输入防注入**：
   - 全面采用 SQLAlchemy 参数化查询，原生免疫 SQL 注入；前端输入在 Element Plus 与后端双向校验。

## 6. 风险评估与应对预案 (Risk & Mitigation)

| 潜在风险点 | 风险等级 | 防范措施与应对预案 |
| :--- | :---: | :--- |
| **服务器端宿主机断电/容器重启数据丢失** | 高 | 在 `docker-compose.yml` 中将 SQLite 数据库文件挂载到宿主机持久化目录（Named Volume / Bind Mount），容器重启数据完全保留。 |
| **单页应用在生产环境刷新 404** | 中 | 在 Nginx 配置文件中加入 `try_files $uri $uri/ /index.html;` 规则，完美支持 Vue Router HTML5 History 模式。 |
| **跨域请求限制 (CORS)** | 中 | FastAPI 后端配置 `CORSMiddleware`，开放安全来源；生产部署时由 Nginx 统一同源反向代理，彻底免去跨域烦恼。 |
| **借阅超期未还违约** | 低 | 系统自动依据当前系统时间与 `due_date` 动态判定超期天数，并提供一键催还与限制新增借阅机制。 |
