# 图书借阅管理系统 (LibraryHub) 功能规格说明书 (Spec)

- **文档版本**：v1.0.0
- **编制日期**：2026-10-21
- **状态**：已评审 / 实施阶段
- **系统名称**：现代化智能图书借阅管理系统 (LibraryHub)

---

## 1. 项目背景与目标

随着数字化校园与社区图书室的发展，传统的人工记账式借阅存在效率低、库存核对繁琐、借还超期统计困难、逾期追踪成本高等痛点。
本项目旨在打造一套高可用、现代化、前后端分离的**图书借阅管理系统**。系统通过清晰的权限划分、严密的图书库存原子管理、智能借还与逾期核算算法，以及直观的统计分析看板，极大提升图书借阅流转效率与读者借阅体验。

---

## 2. 用户角色与权限定义 (RBAC)

系统主要划分三种系统角色，遵循最小特权原则：

| 角色名称 | 角色代码 | 职责定位 | 核心权限范围 |
| :--- | :--- | :--- | :--- |
| **读者 (Reader)** | `reader` | 借阅服务的终端用户（学生/职工/普通读者） | - 个人账号注册与密码维护<br>- 图书检索、分类浏览与图书详情查看<br>- 发起图书借阅、在借图书查看与在线续借<br>- 个人借还历史记录查询、超期提醒查看 |
| **图书管理员 (Librarian)** | `librarian` | 馆藏资源与借还业务日常运营人员 | - 具备读者所有查询权限<br>- 图书入库、书目编辑、分类维护、下架销毁<br>- 线下柜台借阅与代还处理、人工核验<br>- 逾期未还图书催还管理、异常借阅处理 |
| **系统管理员 (Admin)** | `admin` | 系统运维与全站配置主管人员 | - 全局权限：用户账号管理、角色分配、封禁/解封<br>- 系统全局参数配置（借阅天数、最大额度、罚金费率等）<br>- 全站借还统计分析大屏与运营数据导出<br>- 容器健康度与系统审计日志查看 |

## 3. 业务流程与用例规范

### 3.1 核心借还业务流 (State Transition)

```
[图书上架: 可借] 
      │ 
      ▼ (读者发起借阅 / 管理员代借)
[核验准入条件] ──(校验失败: 达到限额/有超期/库存不足)──► [借阅拒绝]
      │ (校验通过)
      ▼
[原子扣减在架库存 (stock - 1)]
      │
      ▼
[生成借阅单 (状态: BORROWED, 记录借出时间 & 应还时间)]
      │
      ├──────────────────────────────┬──────────────────────────────┐
      ▼ (在宽限期内操作)              ▼ (超期归还)                   ▼ (申请续借)
[主动还书 / 柜台扫码还书]       [超期状态标记 (OVERDUE)]       [校验续借次数与超期]
      │                              │ (产生违约金/逾期天数)         │ (仅限1次，延期30天)
      ▼                              ▼                              ▼
[回补在架库存 (stock + 1)]     [完成支付/确认并归还图书]       [更新应还时间并标记已续借]
      │                              │                              │
      └──────────────────────────────┴──────────────────────────────┘
                                     │
                                     ▼
                       [单据结清 (状态: RETURNED)]
```

### 3.2 借阅限制规约 (Business Rules)
1. **最大在借本数**：读者最多同时借出 `5` 本图书（管理员角色可配置）。
2. **默认借阅时长**：单次借阅周期为 `30` 天。
3. **续借限制**：每本图书在未超期前提下仅支持续借 `1` 次，续借时长在原应还时间基础上顺延 `30` 天。
4. **超期阻断机制**：若读者名下存在处于 `OVERDUE` 状态的图书未归还，系统将自动熔断其借阅权限，阻断新的借阅请求。
5. **并发防超卖机制**：借阅扣减库存时必须在数据库事务内进行并发锁防护，严格确保 `available_copies > 0` 且 `available_copies <= total_copies`。

## 4. 功能模块详细说明 (Functional Breakdown)

### 4.1 认证与用户中心模块
- **用户注册与登录**：支持读者自主注册（默认角色为读者），支持用户名/邮箱 + 密码哈希（bcrypt）登录，下发 JWT Bearer Token。
- **个人信息维护**：修改个人头像、联系电话、个人简介、修改密码。
- **借书证卡号绑定**：自动生成全局唯一借书卡号（`CARD-YYYYMMDD-XXXX`）。
- **用户管理（管理员）**：支持管理员对用户列表的分页检索、角色调整、启用/停用状态切换。

### 4.2 图书检索与分类模块
- **分类树管理**：支持多级/多类目管理（如计算机、文学、自然科学、经管社科、艺术设计等），包含分类编号与描述。
- **多维度检索**：
  - 关键词综合检索：按书名、作者、出版社、ISBN 模糊匹配。
  - 条件组合筛选：按分类、上架时间、是否仅看在架有书（库存 > 0）。
  - 排序维度：按出版年份、借阅热度、入库时间、库存数量降序。
- **图书详情展示**：展示 ISBN-13、书名、作者、出版社、出版时间、索书号（架位号）、封面图、内容简介、总藏书量、当前在架余量。

### 4.3 图书采编入库与管理模块（管理员专用）
- **单本新增录入**：输入标准 ISBN、标题、作者、出版社、分类、位置架位、总册数。
- **批量/更新编辑**：支持修改图书基本信息，支持增补入库（增加总册数与在架册数）。
- **下架与报废处理**：若图书全部在架（无借出中记录），允许注销下架；若有未还记录，系统拒绝下架。

### 4.4 借阅与归还管理模块
- **在线借阅申请 / 一键借阅**：读者在图书详情页直接点击“立即借阅”，系统自动校验并生成借阅流水。
- **还书处理**：
  - 读者自主还书提交 / 管理员线下验收还书。
  - 记录实际归还时间，自动计算逾期天数（若超期则按每逾期1天计费0.5元或仅作逾期记录标记）。
  - 自动回补在架图书库存。
- **在线续借**：符合续借条件的在借单据，可一键延长借期。
- **借阅记录流转看板**：
  - 我的借阅（在借中、已归还、已逾期）。
  - 全馆借还监控大厅（管理员侧实时流转监控）。

### 4.5 运营数据分析与仪表盘 (Dashboard)
- **统计总览卡片**：
  - 馆藏图书总种数（Titles）
  - 馆藏总册数（Total Volumes）
  - 当前在借总册数（Currently Borrowed）
  - 注册读者总人数（Registered Readers）
  - 累计借阅总人次（Total Circulations）
- **图表可视化组件**：
  - 近 7 天 / 近 30 天借阅与归还趋势折线图
  - 馆藏图书分类占比饼图 / 环形图
  - 读者借阅热门图书排行榜 Top 10

## 5. 非功能性需求 (NFR)

1. **响应性能**：
   - 常规 RESTful API 接口响应时间 (P95) $\le 200\text{ms}$。
   - 数据库事务采用行锁与轻量查询优化，支持单机数百并发吞吐。
2. **安全性 (Security)**：
   - 密码严禁明文存储，采用 `Passlib + bcrypt` 加盐单向哈希。
   - 鉴权采用标准 `JWT (HMAC-SHA256)` 签名机制，有效规避 CSRF 风险。
   - API 全面开启 CORS 安全白名单与请求头规范校验。
   - 所有输入参数由 Pydantic 强类型严格校验，防止 SQL 注入与 XSS 攻击。
3. **数据一致性 (Consistency)**：
   - 借书与还书操作使用标准数据库 ACID 事务，保障“图书在架量变动”与“借阅流水生成”的绝对原子性。
4. **轻量与可移植性 (Portability)**：
   - 采用标准 SQLite3 数据库引擎，具备零额外外部依赖、单文件存储、快照备份与跨平台迁移特性，同时配合 Docker 挂载数据卷保障持久化不丢失。
5. **容器化交付标准 (Dockerization)**：
   - 前后端解耦构建，前端采用多阶段构建生成 Nginx 静态镜像，后端基于 Python 3.11-slim 镜像。
   - 提供 `docker-compose.yml`，宿主机只需一条命令即可拉起全套服务。
